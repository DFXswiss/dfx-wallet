# WDK Compliance Audit

This document captures the gap between our current WDK integration and the
canonical [Wallet Development Kit documentation](https://docs.wdk.tether.io)
as of **May 2026**.

It is intentionally a snapshot, not a living spec. Re-run the audit when we
plan a WDK upgrade.

## Status

| Audit step | Status | Notes |
|---|---|---|
| 1. Bump `wdk-react-native-core` to `^1.0.0-beta.9` | ✅ done | Off the github commit pin; same for `pear-wrk-wdk` |
| 2. Adopt `@tetherto/wdk-worklet-bundler` for custom bundle | ✅ done | `wdk.config.js` ships only the modules we use (`erc4337`, `spark`, `btc`); bundle generated by `npm run bundle:wdk` (also runs in `postinstall`). |
| 3. Replace manual signing with `useAccount().send()` | ✅ done | `useSendFlow` now uses `useAccount` per chain |
| 4. Migrate `useWalletManager` callers | ✅ done | `restoreWallet`, `unlock`, and wallet-state access use the current provider API |
| 5. Drop `bare-pack@1` preinstall workaround | ✅ done | `pear-wrk-wdk@1.0.0-beta.8` ships its bundle pre-built |
| 6. Add indexer env vars (or document skip) | ✅ documented | Env templates describe the optional indexer values; runtime balance reads intentionally remain RPC-backed. |

## TL;DR

The bundle architecture, provider API, account hooks, and package sources from
the original audit have been migrated. Optional WDK indexer variables are
documented in the environment templates, while the app intentionally uses
RPC-backed balance reads instead.

## Findings

The findings below are the historical May 2026 observations that motivated
the completed migration steps in the status table. They are retained as an
audit trail and do not describe the current tree unless a section explicitly
says that it remains open.

### 1. Bundle architecture — resolved

The docs ([Worklet Bundler](https://docs.wdk.tether.io/tools/worklet-bundler))
specify the production path as:

```bash
npm install -g @tetherto/wdk-worklet-bundler
wdk-worklet-bundler init && wdk-worklet-bundler generate
```

producing a `.wdk/` directory imported as `import { bundle } from './.wdk'`.

At audit time we had **none** of: `@tetherto/wdk-worklet-bundler` installed, a
`.wdk/` directory, or a `wdk.config.js`. We relied on the github-pinned
`@tetherto/pear-wrk-wdk` instead — which the
[React Native Core docs](https://docs.wdk.tether.io/tools/react-native-core)
explicitly call out as the prototype path: *"includes all blockchain modules,
resulting in a larger bundle size"*. The current tree contains
`wdk.config.js`, generates `.wdk/`, and uses the worklet bundler.

### 2. `WdkAppProvider` API — resolved

Docs:

```tsx
<WdkAppProvider bundle={{ bundle }} wdkConfigs={configs}>
```

The pre-migration `app/_layout.tsx` used:

```tsx
<WdkAppProvider networkConfigs={getNetworkConfigs()} tokenConfigs={getTokenConfigs()}>
```

The pinned `wdk-react-native-core` (commit `0b2be6eb`) physically does not
accept `bundle` or `wdkConfigs` props; its `WdkAppProviderProps` only takes
`networkConfigs` / `tokenConfigs` / `currentUserId` / `enableAutoInitialization`.

The migration bumped the core package and adopted the current provider API.

### 3. `wdk.config.js` shape — resolved

Docs ([Configuration](https://docs.wdk.tether.io/tools/worklet-bundler/configuration)):

```js
networks: {
  ethereum: { package: '@tetherto/wdk-wallet-evm-erc-4337' },
  bitcoin:  { package: '@tetherto/wdk-wallet-btc' }
}
```

At audit time there was no equivalent. The current `wdk.config.js` now lists
the shipped modules, while `src/config/chains.ts` carries their runtime
configuration.

### 4. Hooks — migrated

Per the [Core docs](https://docs.wdk.tether.io/tools/react-native-core), the
public hooks are `useWdkApp`, `useWalletManager`, `useAccount`, `useAddresses`,
`useBalance`, `useBalancesForWallet`, `useRefreshBalance`.

| Hook | Used? | Notes |
|---|---|---|
| `useWdkApp()` | ❌ no direct caller | Provider state is consumed through the wallet-manager and account hooks used by the routed flows. |
| `useWalletManager()` | ✅ used | Onboarding, unlock, passkey, seed export, and settings use the current `restoreWallet`, `unlock`, `deleteWallet`, and `activeWalletId` API. |
| `useAccount({ network, accountIndex })` | ✅ used | `useSendFlow.ts` routes sends and fee estimates through chain-specific accounts. |
| `useAddresses()` | ❌ never used | We read the chain-specific address from `useAccount()` instead. |
| `useBalance()` | ❌ never used | — |
| `useBalancesForWallet()` | ✅ used | Used by the balance coordinator and asset/buy-sell views. |
| `useRefreshBalance()` | ✅ used | Wrapped by `src/services/balances/useRefreshBalances.ts`. |

### 5. `@tetherto/wdk-secret-manager` — correctly removed

We removed `@tetherto/wdk-secret-manager` during the WDK migration. The docs
still document it as a standalone tool, but it is no longer required by
`wdk-react-native-core` because `@tetherto/wdk-react-native-secure-storage`
(pulled transitively) handles secret management inside the worklet. Removal
was correct.

### 6. Pricing packages — OK

Both `@tetherto/wdk-pricing-provider@1.0.0-beta.3` and
`@tetherto/wdk-pricing-bitfinex-http@1.0.0-beta.2` match npm `latest`.
Usage in `src/services/pricing-service.ts` is consistent with the
[Price Rates docs](https://docs.wdk.tether.io/tools/price-rates/configuration).

### 7. Android `minSdkVersion` — OK

`34` in `app.json`, well above the docs' required `29`.

### 8. Indexer API env vars — documented, not integrated

The [React Native Quickstart](https://docs.wdk.tether.io/start-building/react-native-quickstart)
requires:

```
EXPO_PUBLIC_WDK_INDEXER_BASE_URL=https://wdk-api.tether.io
EXPO_PUBLIC_WDK_INDEXER_API_KEY=<key>
```

`.env.example` documents an indexer URL and API key, and `.env.testnet`
supplies the public URL while reserving the API key for CI. The runtime does
not currently consume these variables; balance reads intentionally use RPC
directly. Integrating indexer-backed features remains separate future work
rather than an undocumented configuration requirement.

### 9. `bare-pack@1` workaround — resolved

The pre-migration tree pinned `bare-pack@1` for the Pear worklet postinstall.
That workaround was removed when the repository adopted
`@tetherto/wdk-worklet-bundler`.

## Historical migration plan

The audit recommended these commit-sized steps. Items 1–5 are reflected as
completed in the status table; item 6 was resolved by documenting the current
RPC-backed choice:

1. **Bump `@tetherto/wdk-react-native-core` to `^1.0.0-beta.9`** off npm
   (drop the github commit pin). This forces the `bundle` /
   `wdkConfigs` / `useAccount` migration but cleans up the API drift.
2. **Add `@tetherto/wdk-worklet-bundler`** as a dev dependency, write
   `wdk.config.js` (only the modules we ship: `wdk-wallet-evm-erc-4337`,
   `wdk-wallet-btc`, `wdk-wallet-spark`), generate `.wdk/`, swap the
   provider over.
3. Replace `useSendFlow`'s manual signing with `useAccount().send(...)`
   and adopt `BaseAsset` for token definitions.
4. Migrate `useWalletManager` callers to `createWallet` / `unlock` /
   `lock` and the new `state.status` machine in `useWdkApp`.
5. Remove the `bare-pack@1` preinstall workaround once the bundler
   replaces `pear-wrk-wdk`'s postinstall.
6. Add the indexer env vars (or document that we intentionally skip
   indexer features for now).

Each step is independently shippable and worth its own ticket.
